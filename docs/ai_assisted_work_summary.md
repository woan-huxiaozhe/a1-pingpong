# AI 辅助工作的具体运用

> 记录 AI 在 SDK 开发、乒乓球（强化学习 + 传统控制）、以及文档/交接三类工作中的真实落地方式。
> 文中数字与诊断均来自仓库文档与项目记忆，可直接引用。

## 总览

| 领域 | AI 承担的核心工作 | 代表性产出 / 价值 |
|---|---|---|
| SDK 开发 | 接口/架构规范化、跨语言同步 merge、竞品对标优化 | 多语言开发包接口口径统一，人工只做评审 |
| 乒乓球 | 末端控制算法选型验证、对话式数据分析、论文复现、训练实时监控 | 低成本证伪 MPC/LQR、OSC 落地、SAC/BGS 复现并移植 H1 |
| 其他 | 架构文档、跨会话记忆与交接 | 新 Agent 读一遍即上手，接手即复现 |

## 1. SDK 开发

多语言开发包（`C_API` / `C++` / `Python_API` / `Gripper_API` + ROS），跨端接口一致性是主要痛点，机械性工作交由 AI 完成。

1. **规范化、机械性工作全部交由 AI 实现**
   接口命名规范化、架构规范化：统一多语言开发包的命名风格与目录分层（如 `OneroArm_API` 的 `C_API` / `Python_API` / `onero_description`），并同步生成中文 README 与示例代码。
2. **ROS SDK 与 C/C++/Python SDK 同步代码由 AI 安全快速地 merge**
   跨语言接口对齐时由 AI 逐项核对签名、参数与行为一致性，规避人工同步常见的遗漏与口径漂移。
3. **与开源 SDK 对比，分析问题与隐患并直接优化**
   由 AI 对标主流开源 SDK，定位接口设计、错误处理、架构上的问题与潜在隐患，并直接落地优化。
4. **把工程纪律固化进仓库，约束 AI 自身**
   仓库内 `CLAUDE.md` 行为准则（先想后写、最小实现、外科手术式改动、目标驱动验证）减少 LLM 常见编码错误，让多 Agent 协作风格统一。

| 工作类型 | 传统做法 | AI 做法 | 收益 |
|---|---|---|---|
| 接口命名/架构 | 人工逐个对齐、易漂移 | AI 按规范批量生成/重构 | 口径统一、零重复劳动 |
| 多端同步 merge | 人工跨语言搬运、易遗漏 | AI 逐项核对签名与行为 | 安全、快速 |
| 竞品对标 | 偶尔人工 review | AI 系统性对比并直接改 | 隐患早暴露、即时优化 |

## 2. 乒乓球

### 2.1 末端控制算法选型：AI 主导调研 + 低成本验证

AI 基于已有真机击球数据做最小可行实现与离线验证，以极低成本完成方案取舍。

| 方案 | AI 做的验证 | 结论 |
|---|---|---|
| **OSC** | 算法实现 + 数据验证 | ✅ **落地** |
| **MPC** | 简单实现 + 离线验证 | ❌ 证伪不可行（成本极低就排除） |
| **LQR** | 简单实现 + 离线验证 | ❌ 证伪不可行 |

> **关键交叉验证**：理论、部署的传统 task-space 控制器、以及带阻力的 `ideal_racket_velocity` 解算**三者独立都收敛到 ~1.3 m/s 的拍尖巡航速度**——物理目标被证明可达，这后来成为诊断「RL 为何收敛不到它」的存在性证明。

### 2.2 对话式数据分析范式

不再为单个需求单独写脚本——直接在对话框提问，AI 复用现有工具链完成分析并**直接输出调整方向**。

| 维度 | 说明 |
|---|---|
| 数据规模 | 每条 `pingpong_log` CSV ~100 Hz、约 1200 行、数十列 |
| 关键列 | `swing_id/stage`、`ee_plan_pos/vel`、`q_plan/dq_plan`、`q_actual/dq_actual`、`tau_actual/tau_ff`、`orientation_mapper_*` |
| 旧范式 | 每个需求单独写脚本 |
| AI 范式 | 复用 `visualize_log.py`（`load_log` / `segment_trajectories` / `compute_fk_series` + pinocchio FK）分段、对齐、对比 |
| 典型产出 | 算出 cruise 段拍面法向与速度夹角，确认/证伪「回球方向由拍速与拍面法向共同决定」 |

### 2.3 用 superpowers plan 做论文复现并跨本体移植

以 superpowers 工作流（设计 spec → 实现 plan → TDD）参考论文复现算法并移植。

- 在 IsaacLab 上复现 **BGS / SAC** 并**顺利跑通训练**：基于 `ManagerBasedRLEnv` + SAC 事件回放（复用稀有的 `near_miss/hit/return/valid_return` 经验），**完整复现并移植到 H1 环境**。
- **HitTrack 重构**：把端到端接球任务改造为模型化的「击球参考跟踪」，让 **KF 预测与控制策略彻底解耦**；实现纯 torch、无 Isaac 依赖的物理核（`ideal_racket_velocity` 等）并**测试先行（pytest / TDD）**。

### 2.4 后台实时监控训练，在指定节点反馈调整建议

AI 后台盯训练曲线与 rollout，在 plateau / 奖励异常等节点主动反馈并给方向。典型由 AI 主导定位根因的案例：

| 现象 | AI 定位的根因 | 修正 |
|---|---|---|
| 反手 **79% miss** | 参考**侧向未对中**（非时序问题），纯参考 sim 诊断 | `+0.329` 侧向修正 |
| SAC 卡在 **~48° / 3.1 m/s** 的 mis-aimed lob（valid_return ~2%） | **拍面朝向未被奖励** | 引入法向/落点相关奖励 |
| 稠密 `joint_limit` **否决稀疏 `return`** | 惩罚权重 × 密度压过稀疏正奖励 | 松关节 + 稠密过网桥 + drag-aware 净空奖励 |
| 真机/仿真观测延迟不一致 | 逐项观测延迟需区别对待 | 逐项延迟决策 + 真机 KF 发球起始滞后门控 |
| 发球分布与真机不符 | 缺少真实球态标定 | 用 0602 mocap 拟合球速/位置分布 + 空气阻力系数 |

## 3. 其他

### 3.1 仓库架构文档：让新 Agent 快速上手、省上下文

维护 `sac_table_tennis_architecture.md` 这类架构 note，并约定「观测/动作/奖励/回放/延迟/训练环/TensorBoard 日志变更时，必须在**同一次提交内**更新文档」，新 Agent 读一遍即掌握全框架，避免重复啃代码。

### 3.2 工作同步 / 交接：AI 写给 AI 读的文档

| 机制 | 形态 | 作用 |
|---|---|---|
| 设计/实现文档 | superpowers **design spec + implementation plan**（含「已与用户逐项确认」的决策摘要表） | 记录关键设计决策与取舍 |
| 跨会话记忆 | `MEMORY.md` 项目记忆索引 + 各条 root-cause / gotcha 记忆 | 新会话自动加载历史，**接手即复现** |
| 架构文档 | 与代码同提交更新的架构 note | 省上下文，新 Agent 快速对齐 |
